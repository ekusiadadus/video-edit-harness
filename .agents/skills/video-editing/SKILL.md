# Video editing with Video Edit Harness

This skill requires the [Video Edit Harness](https://github.com/ekusiadadus/video-edit-harness) checkout (release `v0.1.0-alpha.7`), Python 3.11+, uv, FFmpeg and ffprobe. The standalone skill ZIP contains instructions and its license; it does not bundle the harness or media.

Find the harness checkout. If `VIDEO_EDIT_HARNESS_ROOT` is set, use that directory. Otherwise, find the checkout containing `pyproject.toml`, `video_harness/`, and this skill; if the skill was copied elsewhere, locate the separately prepared checkout or follow the [installation guide](https://github.com/ekusiadadus/video-edit-harness/blob/v0.1.0-alpha.7/docs/SKILL_INSTALL.md). Ask for its location only when it cannot be determined; do not install dependencies without a request. Run commands from the harness root with `uv run video-harness`. Run `uv run video-harness doctor` first: check the reported root, versions, skills and commands; resolve relevant findings before editing. Read its README.md and AGENTS.md; use `uv run video-harness session --help` for exact command syntax.

Use the current request and existing authorization to establish scope before any cloud upload, message, or publication; ask only when that scope remains unresolved. Honor explicit no-upload and no-publication restrictions for the actual source, including private footage of children. Publishing this skill or harness never authorizes sending its users' footage. With protected footage, continue local grading/audio/technical checks and use an existing sealed transcript when available; if there is none, do not cloud-transcribe it or invent word timings. Use an explicitly permitted alternative source for public demos. Cloud transcription needs authorization for the particular source and credentials in environment variables. The route is OpenAI then Azure OpenAI; there is no local Whisper/ASR. Never synthesize human approval or observations. Record your real actor and keep source footage intact.

For color-only requests, use `preview PROJECT --styles natural,warm_documentary,soft_film` (or styles matching the brief), compare the same source interval, and record the user's choice. A transcript and editorial session are required only for transcript-backed story/pacing edits; do not upload a source just to grade it. Read `docs/PRESET_CATALOG.md` in the harness for use-case/style selection.

1. Copy `projects/talk.template.json` for the project. Replace `source` with the actual absolute media path, set `input_color` and preview interval, and check media tracks. Start `session start PROJECT SESSION --brief-file BRIEF --actor ACTOR`, then inspect `session status SESSION --deep`.
2. Persist the existing source-specific decision once: `session cloud-policy SESSION allow --providers openai azure --actor ACTOR --note BASIS`, or `deny` when uploads are forbidden. The policy is tied to the source SHA; resuming never turns deny/unknown into allow. Do not ask again for an unchanged source/provider already authorized. If source upload is authorized, use `uv run --extra transcription-cloud video-harness session transcribe SESSION`. Or attach a sealed existing transcript with `session transcript SESSION TRANSCRIPT_JSON`. Read the transcript, words, and mismatch warnings. Correct spelling with exact word IDs through `session correct-transcript`; never change timestamps by guessing.
3. Run `session context SESSION --words`. Build a story spec with ordered chapter spans anchored to observed word IDs and omissions with exact IDs, reasons, and goal IDs. `examples/workflow-story.json` shows structure only. Run `session plan SESSION --spec-file SPEC_JSON --actor ACTOR`. Inspect the plan, then `session approve SESSION --actor ACTOR --note REASON`. Agent selection is recorded as agent selection.
4. Render a preview with `session render SESSION`. Review video, audio-only output, subtitles, and frame mapping. Use `session inspect SESSION RENDER_ID --start SECONDS --duration SECONDS` for focused filmstrip, waveform, listening audio, and source words. Use `session audition-junctions SESSION RENDER_ID --offset 0 --limit 24` and subsequent offsets or `--ids` to inspect every needed boundary. The gallery shows remaining IDs. Listen across cut boundaries; protect word endings, breath, emphasis, and topic changes. Visual aids alone are not a listening review.
5. Create a feedback page with `session review-page SESSION RENDER_ID` and import its JSON with `session feedback SESSION --data-file FILE`. Use `session revise` for edit operations or `session address-feedback` for other changes. Re-render and review candidate fixes. Record a six-check review (meaning, pacing, audio_only, cut_boundaries, captions, color) bound to the precise render SHA-256. For more than 24 boundaries, passing cut review also requires exact-SHA `junction_coverage`: `full_listening` with a note, or `selected` with `reviewed_ids` and a reason for each `waived` ID. Do not label generated audition files as listened to. Example review JSON is an unreviewed shape.
6. After acceptance, run `session render SESSION --full`; review that exact full render, then `session package SESSION RENDER_ID --target fcp`. The XML supports a flat, single-source timeline. In actual FCP on macOS, check import, playback, grade/LUT, captions, and mix. Record only performed checks with `session delivery-check`; use `session finish` when its gates pass. The sealed `completion.json` travels inside the delivery folder; `delivery.json` remains the original packaging snapshot. A synthetic completion proves only the fixture workflow, not human acceptance. LUT, SRT, spatial masks, and final audio may need separate application.

Use `session handoff` and `session resume` when switching agents. Keep run logs and hashes. Distinguish synthetic/technical checks, human visual and listening review, FCP GUI proof, and distribution playback. For color comparisons, keep source interval and audio conditions fixed; adopt only a human-reviewed look. Apple Log LUTs already transform to Rec.709, so avoid a second FCP Camera LUT. See README.md and docs/PRESET_CATALOG.md.

In alpha.7, new visual sessions use `visual_pipeline_version: 2`: grade assembled footage before overlays and effects, retaining `visual-graded.mp4`. Do not apply the footage LUT to completed UI or baked FCP picture. Existing unversioned projects preserve pipeline 1; migrate through an unadopted candidate, inspect `visual-pipeline.json`, and retrack the actual pre-effects stage after a grade/pipeline change. Secondary image/comparison colors remain their own; deliberate picture effects can still affect existing overlays. See `docs/VIDEO_EFFECTS.ja.md`.

## Optional editing patterns: shared contract

Use `docs/TRACKING.ja.md` for declared composition protection and local manually seeded tracking. `composition_guides` protects fixed regions or explicit source-bound tracked boxes against supported title/zoom conflicts. Choose LK for textured features, CSRT for appearance tracking, or optional MediaPipe pose for an observed torso; inspect the actual results rather than assuming a backend works for every dance. `session tracking-source` identifies the retained pre-effects picture; `session track-effect` tracks an observed frame interval and proposes an unadopted `tracked_zoom` candidate. Track the exact picture stage used by the renderer. Lost frames, changed input or tracking SHA, and overlapping zooms must fail rather than inventing positions. Pose array indices and geometric/appearance scores are not person identities. Manual correction requires observed boxes. `session track-effect` adds a tracked subject guide: every valid frame is checked for measured title collision and zoom crop. Tracked guides reject split/comparison geometry. Torso boxes do not protect unobserved faces or feet; Automatic title relocation is not implemented. When the current `effects-catalog` includes `tracked_title`, use `session track-effect --effect tracked_title --title-parameters-file` for an explicitly chosen label. Select above/below/left/right and inspect every frame; clipping, lost/stale tracking, declared-region overlap and overlapping zoom/split/comparison geometry must fail. Use `docs/RETIME.ja.md` for source-bound standalone ramp/hold rendering with explicit protected source-frame intervals and observed captions. Prefer retiming source/environment audio before placing added BGM on the new output timeline. Rubber Band R3 is the default audio backend; the phase-vocoder alternative must be explicit and auditioned. Freezes insert silence. The renderer remaps captions to an SRT and reports skipped captions; it does not invent word timing. Visual-session `retime-source` / `retime` proposes unadopted timing candidates with source-frame provenance. Alpha.7 invalidates old explicit cues/effects/guides; development migration follows the retime guide. Added BGM is placed after retiming. Baked mix/video_only FCP handoff retains the result; editable FCP retime and tracking migration remain pending. Speech word protection uses the nonspoken-interval workflow below. Regenerate tracking after a timing change and rebuild cues when explicitly cleared; technical frame/sample checks do not establish human listening quality.

For a request to make the edit less monotonous, first use the actual source to shape a hook, a clear promise, rising information or emotion, and a payoff. Vary shot scale and duration at changes in meaning; choose B-roll that shows the named action, place, object or evidence rather than generic motion. Use a motivated J-cut or L-cut when adjacent source audio and picture permit it, and keep the speaker's words and meaningful ambience intelligible. A selective punch-in, sound hit, brief contrast change or color accent can mark one important turn; leave quieter space before or after it. Keep captions readable and clear of faces, hands, demonstrations and platform UI. Do not apply an effect at every cut or claim it will improve watch time.

Unsupported speed ramps, glitches and FCP third-party plugins must be reported as unsupported rather than counted as applied.
