# Video editing with Video Edit Harness

This skill requires the [Video Edit Harness](https://github.com/ekusiadadus/video-edit-harness) checkout (release `v0.1.0-alpha.7`), Python 3.11+, uv, FFmpeg and ffprobe. The standalone skill ZIP contains instructions and its license; it does not bundle the harness or media.

Find the harness checkout. If `VIDEO_EDIT_HARNESS_ROOT` is set, use that directory. Otherwise, find the checkout containing `pyproject.toml`, `video_harness/`, and this skill; if the skill was copied elsewhere, locate the separately prepared checkout or follow the [installation guide](https://github.com/ekusiadadus/video-edit-harness/blob/v0.1.0-alpha.7/docs/SKILL_INSTALL.md). Ask for its location only when it cannot be determined; do not install dependencies without a request. Run commands from the harness root with `uv run video-harness`. Run `uv run video-harness doctor` first: check the reported root, versions, skills and commands; resolve relevant findings before editing. Read its README.md and AGENTS.md; use `uv run video-harness session --help` for exact command syntax.

Use the current request and existing authorization to establish scope before any cloud upload, message, or publication; ask only when that scope remains unresolved. Honor explicit no-upload and no-publication restrictions for the actual source, including private footage of children. Publishing this skill or harness never authorizes sending its users' footage. With protected footage, continue local grading/audio/technical checks and use an existing sealed transcript when available; if there is none, do not cloud-transcribe it or invent word timings. Use an explicitly permitted alternative source for public demos. Cloud transcription needs authorization for the particular source and credentials in environment variables. The route is OpenAI then Azure OpenAI; there is no local Whisper/ASR. Never synthesize human approval or observations. Record your real actor and keep source footage intact.

For color-only requests, use `preview PROJECT --styles natural,warm_documentary,soft_film` (or styles matching the brief), compare the same source interval, and record the user's choice. A transcript and editorial session are required only for transcript-backed story/pacing edits; do not upload a source just to grade it. Read `docs/PRESET_CATALOG.md` in the harness for use-case/style selection.

1. Copy `projects/talk.template.json` for the project. Replace `source` with the actual absolute media path, set `input_color` and preview interval, and check media tracks. Start `session start PROJECT SESSION --brief-file BRIEF --actor ACTOR`, then inspect `session status SESSION --deep`.
2. Persist the existing source-specific decision once: `session cloud-policy SESSION allow --providers openai azure --actor ACTOR --note BASIS`, or `deny` when uploads are forbidden. The policy is tied to the source SHA; resuming never turns deny/unknown into allow. Do not ask again for an unchanged source/provider already authorized. If source upload is authorized, use `uv run --extra transcription-cloud video-harness session transcribe SESSION`. Or attach a sealed existing transcript with `session transcript SESSION TRANSCRIPT_JSON`. Read the transcript, words, and mismatch warnings. Correct spelling with exact word IDs through `session correct-transcript`; never change timestamps by guessing.
3. Run `session context SESSION --words`. Build a story spec with ordered chapter spans anchored to observed word IDs and omissions with exact IDs, reasons, and goal IDs. `examples/workflow-story.json` shows structure only. Run `session plan SESSION --spec-file SPEC_JSON --actor ACTOR`. Inspect the plan, then `session approve SESSION --actor ACTOR --note REASON`. Agent selection is recorded as agent selection.
4. Render a preview with `session render SESSION`. Review video, audio-only output, subtitles, and frame mapping. Use `session inspect SESSION RENDER_ID --start SECONDS --duration SECONDS` for focused filmstrip, waveform, listening audio, and source words. Use `session audition-junctions SESSION RENDER_ID --offset 0 --limit 24` and subsequent offsets or `--ids` to inspect every needed boundary. The gallery shows remaining IDs. Listen across cut boundaries; protect word endings, breath, emphasis, and topic changes. Visual aids alone are not a listening review.
5. Create a feedback page with `session review-page SESSION RENDER_ID` and import its JSON with `session feedback SESSION --data-file FILE`. Use `session revise` for edit operations or `session address-feedback` for other changes. Re-render and review candidate fixes. Record a six-check review (meaning, pacing, audio_only, cut_boundaries, captions, color) bound to the precise render SHA-256. For more than 24 boundaries, passing cut review also requires exact-SHA `junction_coverage`: `full_listening` with a note, or `selected` with `reviewed_ids` and a reason for each `waived` ID. Do not label generated audition files as listened to. Example review JSON is an unreviewed shape.
6. After acceptance, run `session render SESSION --full`; review that exact full render, then `session package SESSION RENDER_ID --target fcp`. The XML supports a flat, single-source timeline. In actual FCP on macOS, check import, playback, grade/LUT, captions, and mix. Record only performed checks with `session delivery-check`; use `session finish` when its gates pass. The sealed `completion.json` travels inside the delivery folder; `delivery.json` remains the original packaging snapshot. A synthetic completion proves only the fixture workflow, not human acceptance. LUT, SRT, spatial masks, and final audio may need separate application.

Use `session handoff` and `session resume` when switching agents. Keep run logs and hashes. Distinguish synthetic/technical checks, human visual and listening review, FCP GUI proof, and distribution playback. For color comparisons, keep source interval and audio conditions fixed; adopt only a human-reviewed look. Apple Log LUTs already transform to Rec.709, so avoid a second FCP Camera LUT. See README.md and docs/PRESET_CATALOG.md.

In alpha.7, new visual sessions use `visual_pipeline_version: 2`: grade assembled footage before overlays and effects, retaining `visual-graded.mp4`. Do not apply the footage LUT to completed UI or baked FCP picture. Existing unversioned projects preserve pipeline 1; migrate through an unadopted candidate, inspect `visual-pipeline.json`, and retrack the actual pre-effects stage after a grade/pipeline change. Secondary image/comparison colors remain their own; deliberate picture effects can still affect existing overlays. See `docs/VIDEO_EFFECTS.ja.md`.

## Optional editing patterns: shared contract

Use `docs/TRACKING.ja.md` for declared composition protection and local manually seeded tracking. `composition_guides` protects fixed regions or explicit source-bound tracked boxes against supported title/zoom conflicts. Choose LK for textured features, CSRT for appearance tracking, or optional MediaPipe pose for an observed torso; inspect the actual results rather than assuming a backend works for every dance. `session tracking-source` identifies the retained pre-effects picture; `session track-effect` tracks an observed frame interval and proposes an unadopted `tracked_zoom` candidate. Track the exact picture stage used by the renderer. Lost frames, changed input or tracking SHA, and overlapping zooms must fail rather than inventing positions. Pose array indices and geometric/appearance scores are not person identities. Manual correction requires observed boxes. `session track-effect` adds a tracked subject guide: every valid frame is checked for measured title collision and zoom crop. Tracked guides reject split/comparison geometry. Torso boxes do not protect unobserved faces or feet; Automatic title relocation is not implemented. When the current `effects-catalog` includes `tracked_title`, use `session track-effect --effect tracked_title --title-parameters-file` for an explicitly chosen label. Select above/below/left/right and inspect every frame; clipping, lost/stale tracking, declared-region overlap and overlapping zoom/split/comparison geometry must fail. Use `docs/RETIME.ja.md` for source-bound standalone ramp/hold rendering with explicit protected source-frame intervals and observed captions. Prefer retiming source/environment audio before placing added BGM on the new output timeline. Rubber Band R3 is the default audio backend; the phase-vocoder alternative must be explicit and auditioned. Freezes insert silence. The renderer remaps captions to an SRT and reports skipped captions; it does not invent word timing. Visual-session `retime-source` / `retime` proposes unadopted timing candidates with source-frame provenance and invalidated old explicit cues/effects/guides. Added BGM is placed after retiming. Baked mix/video_only FCP handoff retains the result; editable FCP retime and existing cue/tracking migration remain pending. Speech word protection uses the nonspoken-interval workflow below. Regenerate old tracking and cues after a timing change; technical frame/sample checks do not establish human listening quality.

For a request to make the edit less monotonous, first use the actual source to shape a hook, a clear promise, rising information or emotion, and a payoff. Vary shot scale and duration at changes in meaning; choose B-roll that shows the named action, place, object or evidence rather than generic motion. Use a motivated J-cut or L-cut when adjacent source audio and picture permit it, and keep the speaker's words and meaningful ambience intelligible. A selective punch-in, sound hit, brief contrast change or color accent can mark one important turn; leave quieter space before or after it. Keep captions readable and clear of faces, hands, demonstrations and platform UI. Do not apply an effect at every cut or claim it will improve watch time.

Read `docs/VIDEO_EFFECTS.ja.md` before promising a requested visual effect. Translate the requested type, intensity and timing into a `video_effects` project setting: either a `pop_dance`/`subtle` preset with `low`/`medium`/`high` intensity, or explicit version-1 events bound to the exact current frame-mapping SHA. Supported event types are `zoom_pulse`, `split_screen`, `monochrome` and `color_frame`; each explicit event needs an ID, output start/end, strength from 0 to 1 and a concrete reason. A preset anchors to observed cut boundaries, not imagined beats. For a beat-timed effect, use only an actual mapped beat position from the selected local music and its current cue plan; an unknown beat phase remains pending. `natural` or an explicit off direction disables additions; contradictory effect settings must fail visibly. Unsupported speed ramps, glitches and FCP third-party plugins must be reported as unsupported rather than counted as applied.

For `comparison_wipe`, bind a separate registered video with `asset_id`, source-frame-aligned `source_start`, and `layout: wipe` or `side_by_side`. Wipe assumes comparable framing; side-by-side retains both pictures with padding. Preserve base audio only; validate secondary rights, SHA and source range. For `keyword_title`, use explicitly chosen text, measured bounds, readable palette, and fade/rise motion. Record font and generated PNG hashes. These helpers do not detect subjects or prove reading time; inspect faces, hands, existing captions and platform UI.

For parameterized local effects, inspect `video-harness effects-catalog`. `smooth_zoom` supports manual normalized anchors, scale and easing; `saturation_pulse` supports saturation and easing. These are not automatic subject tracking. Use `session effects SESSION RENDER_ID --operations-file FILE --actor ACTOR --note REASON` to add, update or remove events as an unadopted candidate based on that render. Preserve the quiet version and inspect entry, peak and exit. Comparison pages synchronize playback and export selection proposals; a downloaded selection file is not final approval. See `docs/VIDEO_EFFECTS.ja.md` for operations.

Render the plan and inspect effect evidence plus the actual frames across every requested event, including entry, peak and exit. Compare with the quiet version over the same source coverage and audio conditions. Record requested versus applied events, reasons for any rejection, the exact output SHA and a real human viewing/listening decision. A technical render is not perceptual approval. Finished-picture mix or video-only handoff can burn effects into the MP4; do not promise these effects as editable FCP layers. If editable handoff rejects the plan, choose an authorized supported mode or leave the handoff unresolved. The effect implementation and its tests must be confirmed in the current checkout before calling this path supported.

Read `docs/EDITING_PATTERNS_USAGE.ja.md` for the command contract. `session propose-beats SESSION CURRENT_RENDER_ID --spec-file SPEC --actor ACTOR --note REASON` binds a music beat map to the exact render. Explicit nonspoken intervals are required for visual cut movement; the proposed plan needs selection and a new render. Speech plans receive marks only. Never infer permission to cut speech from a low-amplitude signal. `session import-production-fcp SESSION CURRENT_FULL_RENDER_ID XML --actor ACTOR --note REASON` retains a returned production XML and a candidate changes file for supported editable cues; use candidate, render, comparison and explicit adoption. Neither import nor adoption grants human review. Pexels search/fetch have separate permission gates, and a download receipt does not establish rights approval.

For a checkout that exposes `video-harness production --help`, resolve creative direction separately from color (`style`) and scene (`use_case`). Default to `natural`, with no added music, effects, stock visuals or beat sync. A platform name or “trendy” alone does not choose busy editing. The alternatives are `gentle_vlog`, `clear_explainer`, `cinematic_story`, `beat_montage` and `playful_short`; respect explicit per-effect off settings. Save a lasting preference only on an explicit user request, recording the actual actor and reason.

Use `production register SOURCE --metadata METADATA_JSON --output ASSET_JSON` for a local asset. Preserve its license evidence, source URL, credit and SHA. Check `production validate ASSET_JSON --policy POLICY_JSON` for the actual outlets and use. Free price does not establish commercial, advertising, Content ID or redistribution rights. `embedded_use`, `mixed_audio_handoff` and `raw_asset_handoff` are independent. Unknown conditions remain unresolved. Prefer the user's specified asset and own footage, then eligible project/local assets; external search and download have separate permission gates and must not send private transcript text automatically.

For an already selected edit plan, create a comparison with `session candidate SESSION --changes-file CHANGES_JSON --actor ACTOR --note REASON`, render through `session render SESSION --candidate-id ID`, and use `session compare-candidates SESSION RENDER_ID RENDER_ID`. Keep the no-addition option. `session adopt-candidate SESSION ID --actor ACTOR --note REASON` selects the exact immutable snapshot; it never grants human approval or a full-render review. Pattern, music, cue or asset changes require a new exact-render review and matching captions/portrait derivatives.

Explicit cue plans bind to the rendered mapping SHA; use `production cues PROJECT_JSON FRAME_MAPPING_JSON --output PRODUCTION_JSON` to inspect proposed positions. Listen for voice clarity, pumping, loop seams and endings. Beat analysis (`production beats`) is local music signal analysis, not ASR. Inspect ambiguity and frame rounding; do not cut or retime words to follow a beat. Mapping beats does not itself adopt a revised edit.

For footage without speech or an audio track, start a project with `edit_basis: visual` and actual registered source assets. Use `session visual-plan SESSION --plan-file VISUAL_EDL_JSON`, inspect the source-frame selections, then explicitly select the plan. Do not invent a transcript or word IDs. Source environment audio is preserved; missing audio is explicit silence. Review visual context and cuts, adding listening checks when source sound or BGM is present.

Read the local implementation status before promising FCP production handoff. XML/DTD success is not GUI import, playback or re-export proof. Finished-picture mix mode already carries its grade; never apply its conversion LUT again. Editable layers may still require ducking, grade and overlay finishing. Package only the licensed mode, and report every pending observation rather than claiming a completed FCP round trip.

For a catalog advertising title supported_versions [1, 2], version-2 keyword_title/tracked_title can wrap Japanese or English using the local text-layout extra. Set language, max_width_fraction, max_lines and protected_phrases explicitly. Preserve named products and units; never truncate or shrink automatically after overflow. Engine/model bindings and measured wrapped bounds must survive rendering and collision checks. Inspect actual lines and reading time on a phone; wrapping is not semantic or perceptual approval. This capability is included in alpha.7.

For wrapped tracking labels, session track-effect accepts --title-version 2 with the title parameter JSON. Preflight uses the retained pre-effects frame size before tracking, returns measured lines/bounds and binds font/layout evidence; a successful fit does not prove tracked placement is clear of subjects or UI. Keep the candidate unadopted until its rendered comparison is reviewed.

In a checkout with title_collision_checks, rendering rejects overlapping measured keyword/tracked cards on shared visible frames, even without composition guides. Resolve the reported IDs/frame by revising position, width or timing as an unadopted candidate; do not silently move or omit the requested text. Guide-free title clearance proves only title-to-title geometry, not subject/UI clearance or sufficient reading time. Existing overlapping plans may now need revision before rerendering.

In alpha.7, a newly rendered speech session retains speech-base.mov before production additions and normalization; session retime-source returns word_protection bound to the exact plan/transcript/mapping and source. Use original word IDs and occurrence indices, not rounded subtitle times, to inspect protected frames. Unlisted audio is not automatically nonspoken. Alpha.7 speech `session retime` accepts source-bound version-2 settings with explicitly observed `nonspoken_intervals`, mandatory word protection and optional additional protection. Inspect/listen before recording observations; never infer nonspoken intervals from missing words or low amplitude. Render the unadopted candidate to remap grouped subtitles and exact original-frame correspondence, retaining full-resolution assembly and retimed PCM before added audio and normalization. Old explicit cues/effects/guides are invalidated; reapply on the new mapping. Keep original-cut-reference XML and use baked mix/video_only handoff; editable FCP retime remains unsupported. Review the exact final MP4 before adoption or delivery.

For speed/hold comparisons, use `session compare-candidates SESSION NATURAL_RENDER RETIMED_RENDER --mode timing` for independent full-length playback with the same selected plan/source coverage/color/base audio/preview conditions. Read duration and retime-operation evidence; do not treat equal output seconds as equal source moments. The default effects mode remains synchronized and strictly mapping-bound. Timing mode does not compare reordered or different plans. A page selection is a SHA-bound proposal, never adoption or final approval.

For structure alternatives, use `session compare-candidates SESSION FIRST_RENDER SECOND_RENDER --mode structure` with different sealed plans under the same brief/source pool/color/base audio/FPS/preview conditions. Include a natural version without retiming. Inspect ordered original source ranges and reasons, added/removed ranges including repeated uses, duration and retime operations. Play each full video independently; equal output times do not mean equal source moments. Selection exports are exact-video-SHA proposals, not adoption or human review. The default effects mode and same-plan timing mode retain their stricter boundaries. See `docs/RETIME.ja.md`; this capability is included in alpha.7.

Import a downloaded comparison proposal with `session select-comparison SESSION --data-file comparison-selection.json --actor ACTOR --note REASON`. The unadopted candidate restores the selected render's exact plan/project and retained transcript/context inputs, not the current plan with old effects. It validates video SHA, current brief, source and output time. Render the candidate before explicit adoption, then review the exact full output. Restoring older inputs does not restore human approval or publish a video. Legacy speech renders without input references require their actual embedded transcript; context is regenerated from that transcript and the same brief rather than inventing alignment. Included in alpha.7.

For J/L cuts, read `docs/AUDIO_CUTS.ja.md` and use `session audio-cuts` on an exact existing render. Declare actual source-handle and replacement listening observations, `handle_audio_kind`, complete transcript word IDs and repeated-word acknowledgment. Never infer nonspoken audio from missing words. Untranscribed visual speech is unsupported. Render the unadopted candidate, inspect separate audio provenance and rebuilt captions, and require an exact-SHA listening review. Use baked mix/video_only; retime combinations and editable FCP are unsupported. This feature is included in alpha.7.

For `motion_trail`, read `docs/VIDEO_EFFECTS.ja.md` and propose an explicit `session effects` add operation on the actual mapping. Limit it to an observed movement within one shot; do not add it to natural edits. Render the unadopted candidate and compare against natural picture with the same audio. Inspect duplicated faces/hands, baked text, low-FPS stepping and phone readability; `temporal_inputs` proves frame/weight provenance, not aesthetic acceptance. It is full-frame temporal mixing, not a subject mask. This feature is included in alpha.7.

For experimental `tracked_background`, read `docs/TRACKING.ja.md`. Use a full-subject observed box on the retained pre-effects stage, not a torso-only pose box; pose requires manual masks for every selected frame. `session track-effect --effect tracked_background` prepares local GrabCut masks as an unadopted candidate. Keep the manifest/PNG/correction hashes and inspect every contour, hair, hands, clothing and occlusion on the exact rendered comparison. Manual full-size binary PNGs replace individual masks; never hide loss or fall back to a rectangle. Require the SHA-bound `subject_masks` visual check. Baked mix/video_only only; no depth or semantic matting claim. This alpha.7 feature is experimental: an eight-frame real-footage trial kept wall/ceiling in the foreground and the agent rejected the visual result. No human review is recorded. Require full contour review and manual masks before use; do not claim universal person matting.


The post-alpha.7 development checkout offers optional semantic background masks through `session track-effect --effect tracked_background --algorithm pose --model LOCAL_TASK --mask-backend pose`. Confirm these flags in the installed CLI before using them; alpha.7 retains the GrabCut/manual-mask path. Seed the observed torso, retain source/model/library/threshold bindings, and stop on identity loss or ambiguous/mismatched poses. Use full-size binary PNG corrections for incomplete outlines; require the exact candidate render's `subject_masks` visual review. A mask can still lose hands or include another person's overlapping limbs. Do not adopt or call the final MP4 complete from model confidence, successful decode or the agent's frame inspection alone. See `docs/TRACKING.ja.md`.


For the development `session motion-cuts` path, derive adjacent endpoint choices and subject ROIs from actual source frames. Declare only observed nonspoken frame intervals, inspect measured motion and uncertainty, and require explicit plan selection before rendering. Preserve the source/hash/frame/FPS report and rebuild invalidated cues/effects/guides against the revised mapping. Compare structure changes as structure, retain the original render, and obtain new exact-render visual/listening review. Optical direction compatibility does not establish action continuity or camera-motion compensation; overlapping transition rendering remains unsupported. See `docs/MOTION_CUTS.ja.md`.
