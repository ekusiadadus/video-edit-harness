# 見やすさと新しさを両立する編集・エフェクトの実装計画

作成日: 2026-10-06。状態: **実装計画。新機能の実装・受入済みを意味しない。**

対象: Video Edit Harness、共通編集／TikTok／YouTubeスキル、Final Cut Proへの受け渡し。
基準: HEAD `ff39aa9496ed8180a8c0387f4c092643eb52f218` と、現在の未コミット実装を読み取り監査した結果。既存変更は保持する。
既存の[編集パターン計画](EDITING_PATTERNS_PLAN_2026.ja.md)を補完する。素材・権利・音声・セッション管理を作り直さず、エフェクト品質と利用体験を中心に進める。

## 1. 完成させたい利用体験

ユーザーがエフェクト名やJSONを覚えなくても、「どんな動画にしたいか」と局所的な修正で編集できる。

> このダンスをTikTok向けに。動きと音を合わせて、サビだけ少し大胆に。顔と足先を切らず、色の枠は不要。まず自然版と比較したい。

1. 素材と目的を指定する。既存プロジェクトから投稿先・言語・視聴者・好みを引き継ぐ。分かっている事項を再質問しない。
2. 素材に合う「自然」「アクセント」「大胆」の候補を最大3案提示する。初期表示は自然版と推奨1案。名前だけでなく、変更箇所・狙い・制約を示す。
3. 代表区間を同じ場面・音量条件で切り替えて確認する。「ここを弱く」「文字を減らす」「この拍だけズーム」「全部戻す」で修正できる。
4. 採用した方向だけ全編へ展開する。全編の映像と音声を確認し、MP4／FCP受け渡し／TikTok内での仕上げを選ぶ。

これは新しい大規模編集ソフトの開発ではない。最初は既存CLI・スキルとローカル比較ページを結び、少数の分かりやすい操作を提供する。詳細パラメーターは必要なときだけ開く。

初期操作は「強さ」「速さ」「位置」「範囲」「オフ」に限定する。各操作には取り消しと区間プレビューを付ける。プレビュー生成失敗時に旧映像を新しい結果として表示しない。

## 2. MAYAを編集判断へ落とす

ここでのMAYAは、新しさと受け入れやすさを両立する**設計方針**。客観的な万能スコアや、再生数向上を保証する法則として扱わない。「新しい演出30%」などの根拠のない配分は設けない。

| 判断 | 実装する振る舞い |
|---|---|
| 見慣れた土台 | 話の順序、声、動作の意味、読みやすい文字、自然な肌色を先に整える |
| 新しさの焦点 | 見せ場・結果・転換に新しい演出を寄せる。全区間で競合する動きを重ねない |
| 受け入れやすさ | 視聴者の知識、字幕言語、端末、動きへの好みに合わせる。国籍から好みを決めつけない |
| 比較可能性 | 同じ内容の自然版を残し、何を変えたか分かる比較を作る |
| 撤回可能性 | 演出単位で無効化でき、音・字幕・素材選択まで勝手に変更しない |

「自然」はBGM・追加エフェクトを初期オフ。「アクセント」は内容を助ける位置へ限定。「大胆」でも字幕の可読性、主役の視認性、操作説明の正確さを守る。ユーザーの明示指定は優先し、不可能な指定は理由と代案を示す。黙って別の効果へ置き換えない。

本プロジェクトではシアンの装飾枠を推奨から外す。枠を含む装飾は明示指定時のみ。今回の好みを、本人の指示なしに全ユーザーや恒久的な個人設定へ広げない。

## 4. 体系的な編集判断と機能

| 軸 | ユーザーが得る機能 | 判断の記録・受入条件 |
|---|---|---|
| 約束 | 結果先出し／疑問先出しを選べる導入案 | 本編が冒頭の期待に答える。素材にない結果を作らない |
| 構成 | 前提→実演→結果を見渡せる章・見せ場一覧 | 省略した内容と理由が追える。発話は実際のword IDに結ぶ |
| テンポ | 待ち時間短縮、動作・結果を見せる保持時間、緩急 | 説明やダンスの重要動作を飛ばさない。秒数固定の連続カットにしない |
| 視線 | 対象指定のズーム、追従ラベル、比較、背景抑制 | 主役を見失わず、顔・手元・対象を字幕が隠さない |
| 字幕 | 発話字幕／要点ラベル／数値の分離、用語辞書 | 否定・専門語・単位を校正。読む時間と実機表示で確認 |
| 音 | 声中心／音楽中心の切替、フレーズ同期、局所効果音 | 声が聞き取れ、音量差・継ぎ目・過剰な音の反復を確認 |
| 検証 | 同期比較、スマホ表示、無音・音声のみ、局所フィードバック | 技術検査と人による理解・好みの評価を分ける |

日本語は禁則、文節、全角約物、名前・単位のまとまりを扱う。英語等は単語・句のまとまり、長い単語や改行を扱う。画面UIの余白と読み取り時間は言語・端末・内容ごとに検証し、一律の文字数／秒を品質保証にしない。UI安全領域には媒体・画面・確認日を持たせる。

## 5. エフェクトの実装優先度

| 優先 | 機能と狙い | 初期の制限・確認 |
|---|---|---|
| P0 | 対象位置を指定できる滑らかなパンチイン／戻し | 手動アンカーから開始。顔や足先の切れ、拡大ボケ、急な加速を比較 |
| P0 | 重要語・数値だけの文字アニメーション、対象へのコールアウト | 全単語を跳ねさせない。字幕と強調ラベルの衝突を防ぐ |
| P0 | 強拍・見せ場に限定したアクセント、彩度の滑らかな遷移 | 毎拍のズームを避ける。曲の区切りと動作を人が修正可能 |
| P0 | 本物の2素材比較、Before／Afterワイプ | 2入力の時間合わせ・画角・音声方針を明示。鏡像を比較と呼ばない |
| P1 | 動きのつながるカット、J/Lカット、動作方向を合わせたトランジション | ソースの余白と実際の動きを確認。残せない会話や環境音を捏造しない |
| P1 | 被写体追従ズーム・ラベル・マスクによる背景強調 | 手動対象＋追跡修正。追跡喪失時は自動採用せず、該当区間を示す |
| P1 | スピードランプ、フリーズ、限定的な残像 | 時間対応の更新が前提。発話保護、低fps素材の破綻、補間アーティファクトを確認 |
| P2 | 深度・切り抜きの重ね合わせ、複合モーションテンプレート | モデル／実行環境／素材依存を明示。輪郭・髪・遮蔽の破綻を確認 |
| P2 | TikTok・Symphony上の効果や音楽による仕上げ | 実際に使える機能・許諾・アカウント権限を確認して接続 |

フラッシュ、グリッチ、シェイク、強いブラーは既定オフの個別指定とする。派手な効果の数を品質指標にしない。「動きを抑える」選択肢を全パターンに持たせる。点滅の確認はW3Cの面積・輝度差等を含む基準に沿い、単なる回数カウントで適合済みと判定しない。

## 6. ハーネスの設計と責務

以下の新ファイル名は提案であり、既存に同じ責務があれば統合する。

| 対象 | 実装内容 |
|---|---|
| `direction.py`、`patterns.py` | 目的・対象視聴者・言語・自然さ・動き許容・明示した禁止事項を解決。パターンと個別上書きを保存 |
| `effect_catalog.py`（新規）、`video_effects.py` | 版付き効果定義と描画。用途、入力数、パラメーター範囲、イージング、対応backend、制約を定義 |
| `effect_planner.py`（新規）、`cues.py` | どこで何を見せるための効果かを計画。強拍・動作・台詞等の根拠と不確実性を保持 |
| `composition.py`（新規） | 座標・レイヤー・主役領域・字幕・投稿UIの干渉を統一管理 |
| `time_mapping.py`（新規または既存統合） | カット、可変速、フリーズの有理数時間対応。字幕・拍・追跡の再配置 |
| `tracking.py`（新規） | 対象の時系列位置、confidence、遮蔽区間、手動修正。モデル版・入力SHAも保存 |
| `comparison.py`、`session.py`、比較ページ | 同期再生、音声の単独切替、変更理由、局所修正、取り消し、採用操作 |
| `production_fcp.py`、`production_import.py` | 編集可能／焼き込み／未対応を効果別に表示。FCP往復と映像・音声の対応確認 |
| `native_finishing.py`、`tiktok_api.py` | ローカル完成と外部仕上げを分離。権限・取得・適用・再取込・公開状態を区別 |

効果イベントには `effect_id/version`、入力素材SHA、source/output区間、アンカー／追跡参照、パラメーターとキーフレーム、目的・理由、根拠、backend、mapping SHAを持たせる。任意シェル式や未検証プラグインを定義から実行しない。

処理順は、編集構成→リタイムと対応表確定→拍・字幕・追跡情報の出力時間への変換→素材の色調整→合成・エフェクト・文字→音声ミックス→出力・検査を基本とする。色調整の対象を区別し、映像用LUTでUI文字やブランド色まで意図せず変えない。追跡結果の解析時間軸はソース、描画時間軸は出力として明示する。

M0/P0では時間長を変えないエフェクトを先に提供する。リタイム実装時は既存のframe mappingを読み替えるだけにせず、1対多・多対1・停止区間を扱う新しい契約を検証する。音楽に映像を合わせる場合と、音楽側を編集する場合を区別する。発話を無断で伸縮しない。

FCP標準機能は積極的に利用候補にするが、FCPXMLだけで追跡・任意のMotionテンプレートまで再現できると仮定しない。対応確認済みの機能だけ編集可能として渡し、それ以外は焼き込み版と元素材を提供する。外部プラグインは任意導入とし、未導入でも既存セッションを開けるようにする。

## 7. TikTokの音楽・効果を使う経路

| 経路 | 提供する体験 | 確認すべき境界 |
|---|---|---|
| ローカル | 権利確認済み音源で正確な音ハメとMP4制作 | TikTok公式効果の同一実装とは称さない |
| TikTok内の仕上げ | 元動画＋曲の開始位置・効果区間を渡し、アプリ側で仕上げ | 利用曲、地域、用途、アップロード素材への効果適用可否。完成版を再確認 |
| Symphony Creative Studio | 対応する音楽・区間エフェクト・字幕を公式エディターで使用 | Businessアカウント、規約、利用条件、書き出し時のAIラベル |
| Business／Symphony API | 取得可能なカタログ・処理だけアダプター化 | 製品別の権限・審査・費用・エンドポイントを別途検証。Login Kit接続だけで利用可能としない |

2026-10-06確認の動画Direct Post APIには、曲やエフェクトを選ぶパラメーターが見当たらない。これは「TikTokの全APIで音楽・効果を扱えない」という意味ではない。投稿APIと制作APIを分けて調査・実装する。

TikTok内の楽曲で仕上げるときは、選択した曲と開始位置が決まるまで「音ハメ済み」としない。音源ファイルを利用できない場合、無断抽出せず、許される操作でタイミングを確認して最終調整する。TikTok用とYouTube用の音源差し替えは別revisionとして比較・レビューする。

商用音楽ライブラリの利用可否は地域・用途・個別条件を確認する。TikTokで使えることをYouTube等への持ち出し許可と扱わない。Symphonyの公式説明では全書き出しにAI-generatedラベルが付くため、経路選択時に表示する。

今回の計画はアップロード・投稿を行わない。最新のユーザー指定に従い、動画用途を確認してローカルMP4を渡し、YouTubeへのアップロードはユーザーが行う。

## 8. スキルに入れる判断手順

共通規則は `.agents/skills/video-editing/SKILL.md` に集約し、TikTok／YouTubeスキルは媒体差のみ追加する。

1. 目的・視聴者・素材の見せ場を把握し、残すべき声・動作・情報を決める。
2. 指定された効果をcatalogへ解決する。対応済みなら候補に実際に適用し、説明だけで完了しない。未対応なら状態と代案を提示する。
3. 各効果に「対象」「意図」「タイミングの根拠」を付ける。指定がなければ無追加も候補に残す。
4. 自然版と代表区間で比較し、希望された強さへ調整する。自然さと音ハメの両指定なら発話を保護する。
5. 全編で構成、可読性、音、主役、継ぎ目を確認する。機械の検査結果と人のレビューを分ける。
6. 媒体別の仕上げ・権利・FCP再編集性を明示する。採用・人の承認・投稿を別状態として保存する。

参考教材の原理は、出典付きの短い判断カード（用途／避ける場面／例／検証方法）に変換する。有料講座の本文を取り込んだり、未受講の講座を習得済みと表現しない。参考動画を入力した場合も、分析できた構成・動きと推測を分け、素材・曲を無断転用しない。

## 9. 実装順序と完了条件

| 段階 | 作業単位・依存 | 利用者に見える完成条件 |
|---|---|---|
| M0: 契約と比較導線 | 現状のschema・旧描画・権利境界を固定。direction/comparison/sessionを接続 | 同じ区間の自然版と1案を切替再生し、理由を見て採用／取消できる。既存機能を対応済みと誤表示しない |
| M1: 最初の縦断実装 | M0＋パラメーター付きズーム、彩度遷移、対象領域、局所再描画 | 「この拍だけ、顔を切らず、弱く」を反映した比較MP4を作れる。色枠なし。音楽条件が同じ比較で違いが分かる |
| M2: 情報と構図 | M1＋文字、ラベル、2素材比較、音声を含むレイヤー規約 | 解説・ダンスそれぞれで、見せたい対象が分かり、文字・UIが競合しない |
| M3: 動きと時間 | M2＋時間対応schema、手動修正可能な追跡、スピードランプ | 追跡喪失・低fps・発話保護の失敗例を処理し、字幕・音の同期を保つ |
| M4: 外部仕上げ・FCP | M1以後に能力調査、該当機能が整った段階で統合 | 実機でFCP受け渡し、許可されたTikTok等の仕上げを確認。外部機能がなくてもローカル出力可能 |
| M5: パッケージ・文書 | 各機能の受入後 | 実際に使える操作だけをREADME・3スキルへ掲載。クリーン環境のインストールと旧セッション再開を確認 |

**最初の提供範囲はM0–M2。** 追跡・可変速・API接続待ちで、使えるエフェクト改善を止めない。M3以降は別の受入単位とする。API調査とローカル実装は独立に進められるが、schema・session等の共有部分を並行変更しない。

日数は未見積もり。M0で短い実素材の計測を行い、レンダー時間・メモリ・FCP対応可否を確認して見積もる。未測定のリアルタイム性能を約束しない。

## 10. 受入試験・評価

最低限の実素材セットは、権利確認済みダンス、話す人物、細かい操作を示す技術解説。各セットで自然版と演出版を作る。日本語・英語字幕はそれぞれの読みやすさを確認する。少数素材の結果を全ジャンルの優位性と一般化しない。

| 検証 | 必須内容 |
|---|---|
| 意図と描画 | パラメーター変更が実フレームへ反映される。オフが元の描画へ戻る。2素材比較が異なる入力を使用 |
| 破綻ケース | 主役が端へ移動、遮蔽、複数人、暗所、字幕と顔の競合、短いショット、低fps、無音、可変fps |
| 時間・音声 | 完全デコード、対応表とPTS、範囲外参照なし、音ズレ、字幕時刻、末尾、ピーク・ラウドネスと実聴 |
| 見やすさ | スマホ表示、投稿UI、無音、音声のみ、動きを抑えた版。警告がないことと人が快適に見られることは別 |
| 編集の価値 | 初見で主旨・結果・操作が分かるか、見せ場を認識できるか、どちらを好むかと理由を記録 |
| 受け渡し | FCP GUIへ実インポート、編集可能項目の確認、書き出し再比較。XML構文テストだけで完了にしない |
| 再現性 | 素材・catalog・モデル・計画・完成renderのSHA、actor、採用理由、検査ログを保存 |

比較には2モードを設ける。エフェクト比較は同じ構成・音・時間対応で1要素ずつ変更する。構成／リタイム比較は対応表が変わるため、同じ素材範囲と変更点を明示した別モードにする。現状の厳密な同一mapping比較を黙って緩めない。

人の評価は提示順を入れ替え、可能なら案名を隠す。好み・理解・不快な動きを別々に記録する。公開後の維持率や再視聴は補助指標とし、分かりづらさによる再視聴も確認する。自動の総合点だけで作品を採用しない。

実装時は `uv sync --locked`、CLI help、doctorを先に確認し、変更モジュールの試験→縦断レンダー→該当するFCP実機検証の順に進める。全体回帰は統合時に実行する。生ログは `output/` 配下へ保存し、生成物や秘密情報をコミットしない。クラウド転送と料金が発生する処理は既存の素材別許可に従う。

## 11. 互換性と戻し方

旧効果IDと描画版を保持し、既存セッションの見え方を勝手に変えない。新しいズームや本物の分割比較は新バージョン／新IDを使う。移行は新revisionへ書き、旧renderを保存する。backend／プラグイン不足は明示し、別の効果でごまかさない。

各段階は機能単位でオフにできる。候補作成で現行採用版を変更しない。新しいrenderには新しいレビューが必要。既存の人の承認を別SHAへ引き継がない。
