## 1. 目指す体験と設計上の決定

「自然な解説に、章の切り替わりだけ控えめな音楽」「旅の映像を軽快な音ハメで」「BGMも効果音も不要」といった依頼を、再現可能な編集パターンへ変換する。作品の意味と本人の好みを優先し、適合する無料素材を選び、短い比較プレビューから仕上げまで進める。

- 既定は `natural`。追加BGM・追加効果音・ストック映像・音ハメはオフ。元の環境音と意味のある間を保つ。
- 既存の `use_case` は撮影状況、`style` は色調。今回追加する `editing_pattern` は演出方針であり、別の設定として組み合わせる。
- パターンを明示すれば、その範囲で素材候補の選定・配置・プレビューまで自動化する。単に「YouTube用」「流行っぽく」と言われただけで強い演出を採用しない。
- 「おまかせ」は候補選定とプレビュー作成を任せる意味で扱い、既存の計画・最終レンダーのレビューを飛ばす意味にはしない。選曲ごとに同じ確認を繰り返さず、既存のレビュー工程へまとめる。
- 自動選定が不確かな場合は、候補の理由と未確認事項を示す。権利や適合性を確認できない素材を勝手に補完しない。
- 無料は費用条件として扱う。商用利用、改変、掲載先、クレジット、素材の再配布可否は別に判定する。

## 3. パターン案

すべて初期設計案。音量・ショット密度・切替頻度は実素材の比較から調整し、プラットフォーム必須値とはしない。

| ID / 表示名 | BGM・効果音 | 補助素材 | 音ハメ・カット方針 |
|---|---|---|---|
| `natural` / 自然なまま | 追加しない。元の声・環境音を保つ | 追加なし | オフ。既存の発話中心編集 |
| `gentle_vlog` / 控えめな日常 | 歌なしの穏やかなBGM。イントロ・締め、必要な場面だけ。効果音は既定オフ | 本人撮影の写真・手元映像を優先 | オフ。章や場面の区切りのみ、必要なら弱いアクセント |
| `clear_explainer` / 分かりやすい解説 | 発話中は低密度、章切替に短い音。会話への干渉を抑える | 図、ラベル、許可された画面資料。根拠のないストック映像は避ける | 発話を固定し、タイトル・図の表示だけ必要に応じて合わせる |
| `cinematic_story` / 物語を見せる | 曲の展開に合わせた強弱。環境音を残す | 文脈の合う本人素材を優先 | 毎拍ではなく音楽のフレーズ・物語の区切りを重視 |
| `beat_montage` / 映像中心の音ハメ | 拍の明確な曲。強拍に少数のアクセント | 複数ショット・写真・商品の細部など | 発話のない映像区間を拍に合わせる。会話区間の語尾は動かさない |
| `playful_short` / 軽快なショート | 軽い効果音・短い音楽アクセント。密度の上限を設ける | 短い見出し・リアクション補助 | 意味のある強調だけ。全カットへの効果音・過剰なズームは既定で避ける |

個別指定でBGM、効果音、外部素材、音ハメをそれぞれオフにできる。`natural` を選んだ場合は過去の別パターンの効果が残らないよう、解決後設定を保存して確認する。

### 4.2 検索・選定の順序

1. ユーザー指定の音源・素材 → 同じ作品の登録済み素材 → 使用条件を確認したローカル素材庫 → 対応済み公式サービス、の順に探す。
2. 先に掲載先・商用／広告用途・費用ゼロ・許諾・帰属条件で除外する。適合しない素材を雰囲気スコアで復活させない。
3. 残る候補を、場面、感情、エネルギーの推移、歌の有無、音数、長さ、拍の安定性、画角などで順位付けする。歌の有無など不明な属性は推定と表示する。
4. 最大3候補程度の短い比較を作る。原映像・区間・声の音量を固定し、音楽と配置だけの違いを聞けるようにする。無追加版を比較対象に残す。
5. 選定理由、見送った理由、採用者、素材SHA、条件確認日を保存する。既存セッションの再開で最新ランキングに自動差し替えしない。

検索サイトに動画・文字起こしを送る必要はない。外部検索が許可されても、送信するのは本人が公開可能とした一般的な検索語に限定する。検索許可、素材ダウンロード許可、原素材のクラウド送信許可は別に保持する。APIのないサービスは手動取得を案内し、非公開APIやサイト制限の回避を前提にしない。

## 5. 設定・素材・配置のデータ設計

### 5.1 演出設定

ユーザーの自然言語をスキルが次のような構造へ解決し、ハーネスが検証する。**設計例であり既存project.jsonへそのまま追加しても動かない。**

```json
{
  "editing_pattern": {
    "schema_version": 1,
    "id": "gentle_vlog",
    "intensity": "low",
    "music": "intro_outro",
    "sfx": "off",
    "visual_assets": "own_only",
    "beat_sync": "off",
    "selection": "auto_preview"
  },
  "asset_policy": {
    "budget": 0,
    "currency": "JPY",
    "destinations": ["youtube", "instagram"],
    "usage": "monetized",
    "attribution": "allowed",
    "network": "off"
  }
}
```

優先順位は、権利・素材の利用制限を満たしたうえで、今回の明示指示 → 作品設定 → 明示的に保存した好み → パターン既定値 → 全体既定値とする。媒体だけで演出を決めない。「今後も自然な編集を既定に」と依頼された場合だけ、ハーネスのユーザー設定に保存する。過去の一作品の選択を永続的な好みへ自動昇格させない。

パターン定義は新設 `editing_patterns/*.json`、解決・検証は新設 `video_harness/patterns.py` を候補とする。定義のversion/hashと解決後設定をセッションに保存し、定義の更新で既存作品が変化しないようにする。新設のpattern／asset policy schema内の未知の設定値は拒否する。既存project.jsonの拡張項目を一括して拒否する変更は行わない。

### 5.2 素材台帳

新設候補 `video_harness/assets.py`。各素材について次を保持する。

- `asset_id`、ファイルSHA、ローカル参照、種類、作者、原ページURL、取得日時。
- ライセンスURL・確認日時・根拠の保存先、クレジット文、商用／広告／媒体／地域／改変条件。
- `embedded_use`、`mixed_audio_handoff`、`raw_asset_handoff` を分離。素材を含む完成動画、完成音声のみ、元音源・分離トラックの利用／受渡し許可を別々に判定する。
- 費用、Content ID情報・証明書、属性の根拠（作者情報／解析／人の確認）、確認済み・未確認・利用不可の状態。
- 秘密鍵・認証トークンは保存しない。ダウンロード先・サイズ・MIME・パスを検証し、HTMLを音源として採用したりZIP内の実行物を実行したりしない。

保存例は作品フォルダの `assets/` と `harness/session/`。リポジトリ内で試す場合は既存のGit対象外 `media/assets/` を使う。ハーネスのリリースには外部素材を同梱しない。

### 5.3 配置計画

新設候補 `video_harness/cues.py`。`cue_plan` に素材SHA、素材内の範囲、編集後タイムラインの開始・終了、役割、ゲイン、フェード、ダッキング、拍アンカー、選定理由を保存する。秒の浮動小数だけでなく、映像はfpsに基づく分数、音声はsample単位で計算する。

発話の編集計画と演出の配置計画を分ける。発話順の変更・カット変更があれば出力時刻への対応を作り直し、古いBGM位置や字幕を流用しない。画像・Bロールも独立した素材と対応表を持ち、原素材のフレームであるかのように記録しない。

### 5.4 比較候補の保存と採用

現在の `Session.update_project` は現行設定を置き換え、package／finishはレンダーと現行設定・計画の一致を要求する。比較のたびに設定を上書きするだけでは自然版へ安全に戻せない。

そのためcandidateごとに不変の解決後設定、計画SHA、cue plan SHA、レンダーSHAを持たせる。比較時には採用中の設定を変更しない。選択後は対象candidateの設定・計画を新しい現行revisionとして採用し、選定者と理由を記録する。旧candidateを残し、自然版への戻しも同じ操作にする。既存のpackage整合性チェックを外さず、採用された候補と一致する成果物だけを納品する。プレビューの採用は全編レンダーのレビュー承認にはならない。

## 6. 音と音ハメの処理

### 6.1 ミックス

現行の発話PCM結合後に、新設 `video_harness/audio_mix.py` でBGM・効果音を重ねる。追加なしの経路は既存処理を維持する。

- 元音声、音楽、効果音を個別に測定し、声を基準に相対音量を決める。「全BGMを一律−20dB」に固定しない。
- 発話区間の前後を含めた滑らかなゲイン制御を中心に、必要に応じてsidechain compressionを使用する。息継ぎごとに音楽が膨らむポンピングを避ける。低振幅だけで発話や間を削除しない。
- ループは継ぎ目と楽句を確認する。素材末尾、残響、映像末尾のフェード、チャンネル構成、44.1/48kHz差、音声開始時刻を処理する。
- 全ミックスのラウドネス／true peakを測定し、必要な最終処理後に再測定する。既存の目標値は作品設定として継承し、媒体の義務と説明しない。
- 音楽変更で映像の再エンコードが不要な場合は映像キャッシュを再利用する。ミックスのキーには素材SHA、cue plan、duck設定、解析版、FFmpeg条件を含める。

[FFmpeg公式filter定義](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/doc/filters.texi)には `amix`、`sidechaincompress`、`loudnorm` がある。ただし実装時はインストール済みFFmpegの機能をdoctorで確認し、組み合わせた結果を試験する。

### 6.2 音ハメ

新設候補 `video_harness/beats.py`。拍解析は音声認識ではなく、ローカルの音楽信号解析として扱う。ASRや素材アップロードを追加しない。

1. 元音源の拍時刻を検出し、trim／loop／配置後の出力時刻へ変換する。素材をつないだ後は連結点も記録する。
2. 初期は手動指定の拍・BPMと、optional依存のlibrosaを比較する。[librosa 0.11.0のbeat_track](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html)は拍とテンポを返すが、楽句・小節頭や校正済みの確信度を返すものではない。
3. 半分／倍のBPM、テンポ変化、弱い打音、無拍・無音、3拍子などは曖昧さを報告する。独自の安定性指標を「確率」と呼ばず、必要なら手動補正か音ハメなしへ戻す。
4. 会話では音楽・見出し・補助映像を話に合わせる。音に合わせるために単語、語尾、呼吸を切ったり会話を速度変更したりしない。
5. 映像中心の区間だけ、ユーザーが許可した範囲内でカット点を近い拍へ動かす。被写体の動作が途中で切れないことも確認する。
6. 毎拍の切替は必須にしない。ショットの最短保持、許される移動量、楽句の区切りを配置ルールに含める。実装初期は速度ランプ・自動タイムストレッチを対象外とする。

FCPではBeat Detectionを利用して確認・手直しできる。独自のbeat mapとFCP内部の解析結果が同一とは保証せず、初期は通常マーカーと配置情報を受け渡す案を検証する。

## 7. その他素材とFCPへの受け渡し

補助素材は、本人の写真・映像 → ハーネス側で作る簡単な図・見出し → ライセンス確認済み外部素材の順に優先する。出典映像を本人の体験・実績・製品の実映像と誤認させない。必要な場合は「イメージ」等を表示する。字幕、顔、実演対象と重ならないよう全区間で確認する。

現行FCPXMLは単一素材・平坦なタイムラインで、元音声を参照する。BGMをMP4に足すだけではFCPで同じ仕上がりにならないため、次の納品モードを明示する。

- **再現用ミックス**: 完成ミックスPCMを参照するFCPXMLを生成し、元クリップ音声の二重再生を防ぐ。SDRの参照動画と音声を比較できる初期経路。分離音源を含む受渡しが許諾される場合のみ、受渡し素材を同梱する。
- **編集可能なレイヤー**: 後続段階で、Dialogue／Music／Effectsの役割、接続音声、補助映像、ゲイン情報をXMLへ記述する。ダッキングが再現できなければ手動事項として残す。
- **完成動画のみ**: 素材やミックスファイルの別配布条件を満たせない場合、許可された完成MP4と出典情報を渡す。元音源や音楽だけのトラックを黙って同梱しない。

完成ミックスPCMや音声のみの試聴ファイルにも、映像から分離した音声としての利用・受渡し条件を個別に適用する。元音源でないことだけを理由に配布可能とは判定しない。P1のPCM付きXMLは既存flat importの対応範囲を超えるため、レイヤーを読み戻せるP3までは、そのXMLのハーネスへの再importを明示的に非対応とする。FCPへの一方向の受渡しと往復編集を混同しない。

`delivery.py` の固定ファイル一覧を依存manifestへ拡張する。ローカルFCP参照と、他人へ配るportable packageの条件を区別する。権利情報・クレジット・配置情報・SHAを完了記録へ結び付ける。音楽を変えた場合は最終MP4だけでなく、音声のみの試聴出力、縦版、納品レビューも作り直す。

## 9. 実装の順序と受入条件

| 段階 | 範囲・依存 | 完了条件 |
|---|---|---|
| P0: 契約と互換性 | パターン／素材／配置schema、旧セッション移行、natural既定 | 未指定とnaturalで既存の編集・音声経路を維持。未知設定を拒否。元素材・旧記録を上書きせず再開できる |
| P1: ローカルBGMの縦断実装 | P0後。natural、gentle_vlog、clear_explainer。ローカル登録・権利確認・配置・duck・比較・レビュー・納品まで | 一つの許諾済み素材で候補選定→最終MP4を通す。FCPのミックス再現経路を確認し、同梱不可も正しく扱う |
| P2: 効果音・拍同期 | P1後。ローカルbeat解析、手動補正、アクセントと無発話区間のカット | 半拍／倍テンポ・無拍を扱い、単語や語尾を破壊しない。拍と配置の誤差・曖昧さを表示 |
| P3: 補助画像・Bロールと編集可能XML | P1の依存モデルを拡張。本人素材、図・見出し、cinematic_story／beat_montage／playful_short | 複数素材の時間対応、字幕・被写体との重なり、FCP再書き出しを検証。未知XMLを黙って単一素材へ縮退しない |
| P4: 外部サービス連携と傾向更新 | P1の台帳、P3の映像モデルを利用。Pexels等の公式API、他サービスは権利・取得方式を確認して個別追加 | 出典・費用・掲載先・API条件を守り、検索失敗時も既存素材で再現できる。自動取得非対応は明示する |

P1を最初の提供単位とする。音を追加したMP4だけで完了にせず、レビューとFCPへの受け渡しまで閉じる。P2/P3の前提となるH05・H06・H14・H18・H21は[既存バックログ](FCP_HARNESS_BACKLOG_2026.ja.md)と統合し、別々に重複実装しない。

**無言・音声トラックなしの映像:** 現行のセッション編集は文字起こしと元音声を前提としている。P2は既存の発話編集が成立する素材のアクセント・許可された無発話区間に限定する。P3のbeat_montage提供前に、`edit_basis: visual` の経路を設計・実装する。実際のショット範囲／フレームIDに基づくEDLと視覚レビューを使い、架空の単語IDや文字起こしを作らない。無音声素材のrender、BGMのみのmix、音声を必要とする既存チェックの適用条件、frame mappingを対応させる。ここまで通る前に「無言の映像にも対応済み」と表示しない。

傾向情報は `trend_profiles` として出典URL、観測日、対象地域・層、用途、解釈、確認期限を保存する案。自動更新ジョブは初期には設けず、利用者が「最新傾向で更新」と依頼した時に新しい版を作る。古い情報は「当時の傾向」と表示する。素材権利はパターンの観測日とは別に使用時に確認する。

## 10. 検証計画

- **既定動作・互換性:** 旧project/session、パターンなし／natural、自然な版への戻し。固定環境でタイムラインとdecode後の映像・PCMを比較する。コンテナの日時等まで含む全バイト一致を無条件に要求しない。
- **候補の採用:** 同じ発話計画の自然版／BGM版が共存し、比較だけでは現行設定が変わらないこと。選んだcandidateだけがpackage／finishと一致し、旧版のレビューを新しい音へ誤適用しないこと。
- **無発話の経路:** 音声トラックなし／環境音だけの映像と複数ショットを用い、文字起こしを発明せずにvisual EDL・映像対応・BGM mix・レビューを成立させる。未対応段階では明示的に対象外とする。
- **素材・権利:** ライセンス不明、NC素材の商用依頼、クレジット必須、媒体限定、raw同梱不可、同名差し替え、404、破損音源。許諾未確認を成功として通さない。取得はfixtureで模擬し、CIから実サービスへ依存しない。
- **音:** 無音／静かな声／大きな声、長い間、環境音、ステレオ・モノ、44.1/48kHz、短い曲のloop、音源の終了位置。全decode、sample精度の尺、clipping、true peak、最終LUFS、duckの開始・復帰を確認。聴きやすさは実際の試聴で判断する。
- **拍:** 自作クリック・既知テンポ、半分／倍の解釈、テンポ変化、拍なし、3/4、23.976/29.97fps、trim／loop／並べ替え。拍の検出精度とフレームへの丸め誤差を分ける。後者は最寄りフレームへの変換規則を検証する。
- **キャッシュ・レビュー:** 音源SHA、ゲイン、duck、cue、パターン版が変わればmixとレビューが更新される。映像が同じでも旧音声の確認結果を再利用しない。権利情報の変更は少なくとも選定・納品の承認状態を再評価する。
- **FCP:** PCM差し替えで二重音声が出ないこと、追加レイヤーの位置・音量・欠落、relink、rational time、再exportの同期をGUIで確認。DTD合格だけで完了としない。
- **比較レビュー:** 同じ原素材・範囲で自然版／控えめ版／音ハメ版を比較し、声の分かりやすさ、自然さ、疲れやすさ、素材の文脈、好みを記録する。動画の再生回数や主観品質を自動スコアから保証しない。
- **配布:** 外部素材・個人の台帳・認証情報がwheel、sdist、skill/plugin ZIPへ混入しない。使用条件を満たす自作fixtureのみでオフライン再現する。

実装開始時は `uv sync --locked`、doctorと該当CLI help、既存試験でbaselineを保存する。機能ごとの試験に加え、リリース時は全テスト・クリーン導入・配布内容を確認する。今回の試作に対する部分試験は統合機能の受入証拠に含めない。正式な実装では基準コミットと差分を再確認して検証する。

## 11. 初期対象外と未確定事項

自動作曲、声の置換、有料サービスの購入、人気曲の無許諾取得、SNSへの投稿は本計画の初期対象外。初期パターンの音量や密度は実写で調整が必要。FCPの接続音声・ゲイン・通常マーカーの往復は実機検証が必要で、Beat Detection内部情報のエクスポート可否は未確認。外部サイトの素材API・再配布権を一括で確認済みとはしない。

最初に実装する具体的な到達点は、**同じ短いトーク素材から「追加音なし」と「冒頭・締めだけ無料BGM」の二案を作り、本人の選択を記録して、同期したMP4と条件に適合するFCP納品を生成できること**とする。

## 12. 操作契約と実装タスクの切り方

以下はCLI設計案であり、実行可能なコマンドではない。既存CLIと衝突しない名称は実装時にhelpと照合する。

| 操作群 | 入力と保存結果 | 依存／受入証拠 |
|---|---|---|
| `assets register / validate / select` | ローカル素材と権利根拠を登録。用途で先に検証し、適合候補を最大3件と追加なし案で返す | P0→P1。不明条件・改ざん・同名差し替えを拒否し、除外理由を保存 |
| `session pattern / cues` | 明示された演出と強度を解決し、不変の定義版・配置計画・依存SHAを保存 | P0→P1。naturalへ戻すと追加演出が残らず、発話計画の変更で時刻を再計算 |
| `session candidate / compare / adopt` | 現行設定を変えず比較版を作成。選択者・理由を付けて一案を新revisionとして採用 | P1。比較だけで採用されず、採用前後の音とレビューを混同しない |
| `beats analyze / import / map` | ローカル解析または手動拍から、素材時刻・出力時刻・フレーム誤差を保存 | P2。曖昧な解析は手動補正／オフへ戻せる。会話範囲を保護 |
| `session visual-plan` | 実際の素材IDとショット範囲からvisual EDLを作成・レビュー | P3。無音声・複数素材で実行し、架空の文字起こしを要求しない |
| `assets search / fetch` | 別々に許可したネットワーク操作から公式APIで検索・取得 | P4。検索語の非公開情報を除き、出典・API条件を保存。失敗時は既存素材で継続 |
| `trends import / inspect` | 調査済み出典と対象・日付・確認期限を持つ新しい版を登録 | P4。期限切れを表示し、旧セッションを遡って書き換えない |

ハーネスは型・権利・時刻・再現性を検証する。スキルは依頼の解釈、候補の説明、文脈・自然さの確認、実際のレビューを担当する。スキルの文章だけで権利ゲートやレビューゲートを解除できる設計にはしない。

実装は「パターン・素材台帳」「音声・拍・配置」「セッション・CLI・FCP／納品統合」の責務に分ける。schemaと共有APIを先に合意し、独立した作業のみ分担する。自然版とBGM版を縦断で通した後に、補助素材・visual EDL・XML往復へ広げる。各段階で実装差分、試験ログ、生成物SHA、未確認事項をまとめ、READMEと3スキルには実際に通った操作だけを記載する。

### 13.2 スキルの依頼解釈と比較手順

スキルは目的・掲載先・話の有無・演出の好みからパターンを解決する。依頼が具体的ならそのまま候補作成へ進み、不足が結果を左右する場合だけ質問する。自然さと音ハメの両方が指定された場合は、発話を保護したまま無発話区間へ音ハメを限定する。無料という条件は`budget: 0`へ、広告や収益化の条件は利用ポリシーへ分離する。

| 指示例 | パターンと処理 |
|---|---|
| 「自然な会話を中心に。音楽は不要」 | `natural`。追加音・外部映像・音ハメをオフ |
| 「日常Vlog。無料の穏やかなBGMを冒頭と締めだけ」 | `gentle_vlog`。歌なし候補、疎な配置、効果音オフ。無追加版と比較 |
| 「解説を分かりやすく。声を邪魔せず図を付けて」 | `clear_explainer`。章の切替と根拠のある図を優先。発話カットを拍に動かさない |
| 「旅行の無言映像を軽快な音ハメに。環境音も残す」 | `beat_montage`＋visual EDL。動作と最短保持を守り、許可区間のカット提案をレビュー |
| 「最新の流行でおまかせ」 | 対象と目的に合う版付きtrend profileを参照。自然版と演出版を提案し、強い演出を自動採用しない |

### 13.3 最初の提供単位の完成判定

P1の完成には、自然版と控えめBGM版の比較、選択した全編の視聴・試聴、正しいクレジット、許諾されたMP4／FCP納品、別フォルダからの読込が必要。自然版へ戻せることと、無許諾の音源・分離音声を納品しないことも確認する。その後に音ハメ、補助映像、外部検索を段階的に提供する。未確認機能をREADMEやスキルで「対応済み」と約束しない。
