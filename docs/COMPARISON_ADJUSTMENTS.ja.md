# 比較ページからエフェクトを調整する

開発版の `effects` 比較ページでは、選んだ案のエフェクトを弱めたり、個別にオフにできます。元の映像と編集設定は残ります。公開済み alpha.7 には含まれません。

1. `uv run --no-sync video-harness session compare-candidates SESSION NATURAL_RENDER EFFECT_RENDER` で比較ページを作成し、表示された HTML を開きます。
2. 「この案を候補に選ぶ」で対象を選びます。調整欄で強さを変更するか「オフ」を選びます。案を切り替えても各案の調整は保持します。「直前の調整を戻す」「この候補の調整をすべて戻す」で取り消せます。
3. 「選択と修正メモを保存」で JSON をダウンロードします。画面の動画は元のままです。スライダー操作は再レンダーや採用を行いません。
4. `uv run --no-sync video-harness session select-comparison SESSION --data-file comparison-selection.json --actor codex --note '比較で指定した調整を候補化'` で未採用の候補を保存します。
5. `uv run --no-sync video-harness session render SESSION --full --candidate-id CANDIDATE_ID` で実際の映像を生成し、映像と音を確認します。必要なら新しい比較ページを作り、調整を繰り返します。
6. 採用する場合は `uv run --no-sync video-harness session adopt-candidate SESSION CANDIDATE_ID --actor codex --note '修正版を確認して選択'`。採用とは別に、正確な出力 SHA に対する全編レビューを残します。

変更がない場合は従来の version 1 選択 JSON、変更がある場合は version 2 と `effect_operations` を保存します。version 2 は既存のイベント ID に対する強さ変更（0 より大きく 1 以下）と削除だけを受け付けます。未知の ID、重複操作、非数値・無限値、不正なパラメーター、古い動画 SHA は拒否します。合成・二分割・白黒など強さが映像へ反映されない効果はオフだけを表示します。

リタイムで保存した `phase_map` の効果は調整欄に出ません。`content_map` を含む候補は効果全体の順序・設定に依存するため、このページから調整できません。元の通常速度の候補を選んで調整し、必要なリタイムを改めて作成します。保存済みの時計や映像の結び付きを削除して強制適用しません。

追跡対象・BGM の変更はこのページから提供しません。効果の区間確認には下記の `preview-changes`、採用前には通常の全編レンダーを使います。選択 JSON は採用・人の承認・アップロードの記録ではありません。投稿はユーザーが行います。

## 修正区間を音付きで比較する

調整元と修正版の両方を全編レンダーした場合、次の開発版コマンドで変更区間の比較を作れます。

```sh
uv run --no-sync video-harness session preview-effects SESSION REVISED_RENDER \
  --effect-ids EFFECT_ID --context-frames 8
```

`--effect-ids` を省略すると修正した全エフェクトを含めます。前後の余裕はフレーム数で指定し、タイムラインの端で切り詰めます。オフにした効果は調整元の区間を使います。出力先の `preview.html` で調整前・調整後の音付き区間を確認します。両動画は完成映像から同じ出力フレーム範囲を切り出し、効果や音楽を最初から適用し直しません。

`preview.json` には全編の動画 SHA、対応表、正確なフレーム範囲、元の素材との対応と短い映像の SHA を残します。フィードバックと全編レビューの対象は修正版の全編 SHA です。区間を見るだけでは全編のレビューが完了しません。

プレビュー版だけのレンダー、変更対象以外の効果 ID、対応表の不一致、30 秒を超える区間は拒否します。長い／離れた変更は `--effect-ids` を分けて確認します。失敗時は未完成の映像を成功したプレビューとして表示せず、ログと失敗結果を残します。

これは完成映像を使った区間確認です。効果の区間だけを先に再レンダーする高速処理ではありません。映像は区間を再符号化し、音声も視聴用 AAC に再符号化します。元の完成ファイルは保持します。

対象はハーネスの通常出力と同じ 8-bit yuv420p の完成 MP4 です。色タグを固定して上書きせず、親映像の解釈を保持します。音声の切り出し位置は `audio_sample_bounds` に 48 kHz のサンプル番号で残します。既存の出力フォルダーを上書きしません。


## 区間とズーム位置を変える

開発版の比較ページは、通常の効果に「開始フレーム」「終了フレーム（含まない）」を表示します。出力タイムライン上で、例えば開始 12・終了 24 は 12〜23 フレームへ適用します。短すぎる区間、動画の範囲外、整数ではない指定は保存できません。各効果の最小フレーム数も検査します。

滑らかなズームでは「横（左0／右1）」「縦（上0／下1）」を 0〜1 で指定できます。強さ・区間・位置の変更には同じ取り消し・リセット操作を使います。区間・位置が変わると version 3 の JSON を保存し、従来の `select-comparison` で未採用の候補に反映します。従来の version 1・2 も受け付けます。任意パラメーター、効果種別の変更、素材の追加はこの JSON ではできません。

時刻は実際の FPS から正確な有理数で保存するため、30000/1001 等でもフレーム位置を小数秒へ丸めません。追従効果の区間は、追跡データとの対応を保つためこのページから変更できません。必要な区間で追跡データを再生成します。保存されたリタイムの時計・映像に依存する効果の制限も保持します。

修正後の候補をレンダーし、対象の切れや字幕との競合を確認します。候補への保存だけでは描画検査・人のレビューが完了しません。`preview-effects` は元と変更後の区間を両方含めるので、移動前の効果が消えた場所も比較できます。30 秒を超える場合は対象を分けるか全編で確認します。

## 全編を待たずに修正区間を描画する

`select-comparison` が返した未採用の候補 ID で、変更区間を先に確認できます。

```sh
uv run --no-sync video-harness session preview-changes SESSION CANDIDATE_ID \
  --effect-ids EFFECT_ID --context-frames 8
```

元の全編レンダーに保存したエフェクト入力の SHA が一致する映像を再利用します。素材の組み立て・色調整・重ね素材・音声ミックスを作り直さず、修正後の効果を描画し、元と変更先を含む区間だけを書き出します。効果の時計と残像の履歴を保つため、区間末尾までの元映像は処理します。後半の区間でも処理時間が一定になる方法ではありません。

音声は元の完成ミックスを同じ出力フレーム範囲で切り出します。色調整と効果の処理順・中間符号化も元のパイプラインに合わせます。区間の新しい符号化境界により、通常の CRF 出力は全編から切り出した画素と完全一致するとは限りません。全編を描画済みなら `preview-effects` で完成ファイル同士を比較できます。

保存先の `preview.html` は前後の音声切替・同期再生に対応します。`preview.json` に元の完成動画、保存入力、候補設定、対応表、区間映像の SHA と処理時間を残します。これはセッションの全編レンダー一覧へ登録されず、区間だけを作った候補は採用できません。採用前には `session render --full --candidate-id` を実行し、その正確な出力の映像と音声を確認します。

対象は version 2/3 の比較修正候補です。保存入力の改変・喪失、編集計画や効果以外の変更、30秒を超える範囲は拒否します。失敗時には未完成の MP4 とページを除去し、失敗結果・ログを残します。公開 alpha.7 には含まれません。
