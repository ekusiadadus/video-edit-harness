# BGMの音量変化を保存する開発機能

音ハメ編集で、声に合わせたBGMの抑制やフェードを後から確認できるように、ミキサーが実際に適用した音量変化を保存します。音声キューのある通常のセッション描画で生成されます。追加のコマンド操作は必要ありません。公開済みalpha.7には含まれません。

## 保存する内容

`audio-envelopes/manifest.json`とキューごとの数値配列に、48 kHzのサンプル単位でフェード、ダッキング、ループ継ぎ目の音量を記録します。全体のピーク抑制係数は別に保持します。素材、声の入力、ミックスWAVのSHA-256とキューの時刻・設定に結び付け、読み戻しで内容を照合します。数値配列はpickleを使いません。

発話編集では`audio-mixer-speech.wav`と`audio-mixer-input.wav`、映像編集では既存の`environment.wav`と`creative-mix.wav`を保持します。キャッシュ利用時も入力WAVと音量配列を検査してコピーするため、キャッシュから再描画した場合にも同じ証跡を残します。欠損・改変・別素材の証跡を流用しません。

`audio-gain-evidence.json`はこれらのローカルファイルを指すセッション証跡です。manifest自体はパスを含みませんが、この参照ファイルと既存のセッション証跡にはローカルパスが含まれます。公開配布用の匿名化済み資料として扱わないでください。

## 現時点の範囲

保存するのは最終ラウドネス補正前のミックスです。処理済みステム、最終ラウドネス補正、実際のFinal Cut Pro再生との一致は未完了です。既存の完成音声を焼き込む引き継ぎと区別してください。

## 編集可能な音量キーフレームを試す

開発版のプロジェクト設定で、明示的に次を指定します。通常の描画・FCPパッケージ手順で音量証跡を照合し、声のPCMとBGM・効果音を独立した接続クリップとして書き出します。素材のraw_asset_handoff権利が必要です。

```json
{"fcp_handoff": "editable", "fcp_audio_automation": "measured"}
```

既存の音声キューが必要です。キューの音量配列をループごとに分け、素材の開始時刻を基準にキーフレームを配置します。全体のピーク抑制を声と各キューに適用し、元の主映像クリップはXMLで映像のみへ指定します。最終ラウドネス補正は適用しません。FCPで主素材の音が再び有効になっていないかも確認してください。

生成する線形dB補間の係数を全サンプルで再計算し、元の音量係数との差が2e-5以下になるまで点を追加します。ゼロは-96 dBで近似し、その差も検査します。+24 dB超、必要な点が20,000超、極端に複雑な曲線で計算上限に達した場合は拒否します。これらは係数の技術的な誤差検査であり、FCPの補間・素材読み出し・実際の音の一致を証明しません。

`fcp-production.json`にはpre_normalizationとpending_fcp_gui_calibrationを記録します。DTDと構造的な読み戻しを検査しますが、実FCPでインポート、再生、音量点とロール、書き出し音声を確認する必要があります。この音量キーフレーム付きXMLの編集結果をセッションへ戻すインポートは、現時点では拒否します。普通の完成動画用には、レビュー済みの最終ミックスを保持するmix引き継ぎを使ってください。

音量証跡を保存する有無で既存ミックスのPCMを変えないこと、サンプル境界、キャッシュからの復元、改変拒否を技術試験で確認します。人の試聴や完成動画の承認とは別です。声の聞き取りやすさ、音ハメの自然さ、ループ継ぎ目は、実際のMP4を通して確認してください。最終レビューはそのMP4のSHA-256に結び付けます。

YouTube向けには用途を確認してから構成を決め、完成MP4を渡します。今回の投稿はユーザー自身が行います。
