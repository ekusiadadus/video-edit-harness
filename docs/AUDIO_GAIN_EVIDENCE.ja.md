# BGMの音量変化を保存する開発機能

音ハメ編集で、声に合わせたBGMの抑制やフェードを後から確認できるように、ミキサーが実際に適用した音量変化を保存します。音声キューのある通常のセッション描画で生成されます。追加のコマンド操作は必要ありません。公開済みalpha.7には含まれません。

## 保存する内容

`audio-envelopes/manifest.json`とキューごとの数値配列に、48 kHzのサンプル単位でフェード、ダッキング、ループ継ぎ目の音量を記録します。全体のピーク抑制係数は別に保持します。素材、声の入力、ミックスWAVのSHA-256とキューの時刻・設定に結び付け、読み戻しで内容を照合します。数値配列はpickleを使いません。

発話編集では`audio-mixer-speech.wav`と`audio-mixer-input.wav`、映像編集では既存の`environment.wav`と`creative-mix.wav`を保持します。キャッシュ利用時も入力WAVと音量配列を検査してコピーするため、キャッシュから再描画した場合にも同じ証跡を残します。欠損・改変・別素材の証跡を流用しません。

`audio-gain-evidence.json`はこれらのローカルファイルを指すセッション証跡です。manifest自体はパスを含みませんが、この参照ファイルと既存のセッション証跡にはローカルパスが含まれます。公開配布用の匿名化済み資料として扱わないでください。

## 現時点の範囲

保存するのは最終ラウドネス補正前のミックスです。音量変化の保存だけでは、編集可能FCPXMLの音量キーフレーム、処理済みステム、最終ラウドネス補正、実際のFinal Cut Pro再生との一致は実現していません。これらは次の実装工程です。既存の完成音声を焼き込む引き継ぎと区別してください。

音量証跡を保存する有無で既存ミックスのPCMを変えないこと、サンプル境界、キャッシュからの復元、改変拒否を技術試験で確認します。人の試聴や完成動画の承認とは別です。声の聞き取りやすさ、音ハメの自然さ、ループ継ぎ目は、実際のMP4を通して確認してください。最終レビューはそのMP4のSHA-256に結び付けます。

YouTube向けには用途を確認してから構成を決め、完成MP4を渡します。今回の投稿はユーザー自身が行います。
